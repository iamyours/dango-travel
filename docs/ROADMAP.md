# 开发路线图

《团子去旅行》继续做成轻松、治愈的放置游戏，并按这个顺序准备 [TapTap](https://www.taptap.cn/) 首发。任务认领与进度只看 [TASKS.md](TASKS.md)。协作步骤见 [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md)。手机端布局见 [MOBILE_UX.md](MOBILE_UX.md)。

背景材料：

- [2026-11-04 设计分析](research/muse-analysis-2026-11.md) 与 [现状简报](research/game-brief-2026-11.md)（`main@2cad3db`）
- [2026-11-04 操作简化与手机端方案](research/muse-simplify-mobile-2026-11.md)，基线截图 [mobile-baseline-2026-11.jpg](research/mobile-baseline-2026-11.jpg)

分析原文里的「天 / 周」是当时的工期感觉，不是本路线图的承诺。工作量用任务板上的「难度」表示。版号、软著、正式实名防沉迷是外部事项，不进开发估算。

先把 7 个标签收成 4 个底部 Tab，并让出发从 16 次点击、3 次切页降到 3 次点击、0 次切页。这套流程在网页上通过 P0-17 之后，再做 Capacitor。不要把现在的界面原样套进安装包。

## 硬约束

全程有效，任何阶段的 PR 都不能突破：

1. **广告只有一个。** 玩家主动点的激励视频（rewarded ad）只出现在出行确认 Sheet 或出行页的差额状态：余额小于本次合计时，主按钮下方有一条次级按钮，看完补三叶草，Sheet 不关闭。余额够时不出现。教程首旅不出现。不自动弹出，也不和出发按钮合成「看了才能走」。不做横幅、插屏、开屏。P0-15 定下这个位置；在那之前不要新增第二个入口。
2. **不做这些系统：** 排行榜、PvP、体力、失败惩罚、断签惩罚、限时错过就扣已有收藏。
3. **文案中英一起上。** 新的玩家可见文字同时写入 `assets/i18n/zh.js` 和 `assets/i18n/en.js`。逻辑用 key。不要新增硬编码中文。少做一个目的地，也不要先上中文、以后再补英文。
4. **每个内容包最多 2–3 个新目的地。** 室内房间、客厅皮肤、粒子和节日访客不算目的地。每个目的地带 3 段递进日记（中英）和可选的 1 个纪念品。
5. **`main` 随时能部署。** 站点同步与本地验证见协作约定。不要把玩到一半的 `index.html`、`assets/` 或 `koi/` 留在 `main`。

## 外部事项

下面四项由作者、出版社或 TapTap 后台推进。任务板上有对应行，方便同步状态。它们的等待时间不算进开发估算，可以和开发并行。它们不挡住无广告的网页改动和测试包，但挡住带激励广告的版本（P1-08）。

| 事项 | 任务 | 和开发的关系 |
| --- | --- | --- |
| 版号（网络游戏出版物号） | P1-27 | 广告变现也算商业化。首发可以先走免费、无内购的测试形态。结论没写明前不要接 P1-08。这不是法律意见。 |
| 软件著作权 | P1-28 | 建议尽早申请。不阻塞无广告开发。 |
| TapTap 开发者实名认证 | P1-29 | 入驻需要。不产生游戏代码。 |
| 正式实名与防沉迷 | P1-30 | 只有按正式版号运营时才接入。测试形态只做 P1-25 的忠告、适龄和时长提醒，不收集身份证。 |

## 现在已经有的，不要推倒重做

`main@2cad3db` 上已经有这些能力。相关任务的验收是补缺口，不是另做一套：

- 存档对象已有 `v: 3`，并有从旧 key 搬到当前 key 的一次迁移。还没有导出/导入，也还没有「以后加字段」用的迁移函数。
- 激励广告已有每日上限，按钮上会写出奖励数量。实现仍是 AdSense H5 `adBreak`，`index.html` 里 `data-adbreak-test="on"`。P0-15 把这一个入口挪到差额状态，不在商店和确认层各留一个。
- 阳台四种作物可以在厨房做成三道带目的地倾向的食物。
- 家具可以拖拽、缩放、收回。还不能旋转。
- 点团子会挥手。主游戏声音是代码里的振荡器，不是可替换的音效素材。
- 春、秋、冬客厅有独立背景。夏季分支目前用 `home_empty`。
- 页脚的隐私政策指向站点上的 `/privacy/`，页面不在本仓库。改版后链到顶栏「⋯」。

## 阶段 0 — MVP 补完

仍在网页版。目标是新流程能出发、第一圈当天能开箱、存档和声音补上、手机尺寸过得去。P0-17 是进入 Capacitor 的门。

### 目标

- 底部变成 4 个 Tab。常规出发 3 次点击、0 次切页。自己改组合不超过 5 次。
- 新玩家按「选目标 → 确认 → 出发」完成引导，并在 5–10 分钟内体验回家开箱。教程首旅不出现广告。
- 玩家能自己备份存档；以后加内容时旧档不会坏。
- 打包、出发、回家、点击、雨声有声音。点团子是摸摸，和滑动换房间分得开。
- 资源本地加载并压缩。360 / 390 / 430 和平板 600px 列上，中英都不截断。

### 范围

要做的是 P0-01–P0-09、P0-11–P0-17，以及提前进来的 P1-14。P0-10 并入 P0-15，不单独做。

- P0-11 信息架构，P0-12 触控、安全区和返回栈，P0-13 房间滑动。
- P0-15 出行页、推荐确认和规则提示；P0-14 一键收取、一键开箱、再来一次。
- P1-14 摸摸团子，与房间手势同一批定点击语义。
- P0-01、P0-02 在新流程上写引导和短首旅。
- P0-03、P0-04 存档导出与 version 迁移。P0-05 音效。P0-06、P0-07 图片与脚本本地化。
- P0-16 语言和宽度。P0-08 埋点含交互漏斗，并更新隐私说明。P0-09 白屏兜底。
- P0-17 找 5 名新玩家做无提示验收。

本阶段不加新目的地，不做 TapTap 包，不接原生广告 SDK。离线安装用阶段 1 的 Capacitor 解决，不另做 PWA。

### 退出标准

1. 首页、出行、池塘、收藏四个 Tab 覆盖原来的核心功能，池塘没有第二入口（P0-11）。
2. 功能点击区至少 48×48，返回顺序符合规格，返回不会扣三叶草（P0-12）。
3. 手机上靠滑动和房间列表换房间，访客和成熟作物在列表里看得见（P0-13）。
4. 收取不超过 1 次点击；开箱领取不超过 1 次点击；动画中途杀掉进程不丢、不重复领（P0-14）。
5. 已有库存时，出发不超过 3 次点击、0 次切页。未拥有的食物在一次确认里买完并出发。推荐理由写在 Sheet 上。收藏里的空格子能点开说明（P0-15，含原 P0-10）。
6. 引导教的是新流程，第一趟 5–10 分钟，确认层没有广告（P0-01、P0-02）。
7. 轻点团子是摸摸，滑动换房间不会误触（P1-14）。
8. 导出的存档能导回；带 version 的旧档能迁移（P0-03、P0-04）。
9. 五个声音场景可开关（P0-05）。图片走 WebP；锦鲤池断外网 CDN 后仍能打开（P0-06、P0-07）。
10. 360、390、430 和平板 600px 列上，中英主按钮和导航不截断、不重叠。首启语言与系统一致（P0-16）。
11. 埋点能看到原有三个事件和四项漏斗；脚本错误时有可恢复提示（P0-08、P0-09）。
12. P0-17：至少 4/5 的新玩家能独立走完首旅，出发前点击中位数不超过 5，误触消费为 0。

未达到第 12 条时，不开始 P1-01。分析里的「首次打包转化明显高于无引导」仍是希望看到的方向，不是对外承诺的数字。

## 阶段 1 — TapTap 首发

把已经通过 P0-17 的网页做成可安装的测试包。首发内容只加一个新目的地。审核和版号的日历不进本阶段的开发估算。

### 目标

- Capacitor 安装包断网能开，回程有本地通知。通知权限在首旅开箱之后再问。
- 先以无广告的免费测试包看崩溃率和留存。原生激励 SDK 接在 P0-15 定下的那一个差额按钮上，并且要等 P1-27 的结论。
- 首发场景是夏日海滩、夏季客厅，再加一套节日皮肤和纪念品展示间。夜市放到阶段 2 的第一包。
- 商店材料和游戏内合规提示齐套。测试区先跑，再转正式页。

### 范围

**安装包（P1-01、P1-02、P1-03、P1-05，以及复验 P1-04、P1-06）**

- Capacitor 工程。不采用裸 WebView 套网址，也不把旧的 7 标签套进去。
- 存档迁到 Preferences 或文件，保留 localStorage 兜底。
- 按回程时间预约本地通知。授权文案只说提醒团子到家，拒绝没有任何惩罚。
- 断网冷启动不白屏。安全区、返回键和 360 / 390 / 430 / 平板列在真机上再走一遍（P1-04、P1-06），规范本身在 P0-12、P0-16。

**广告（P1-07、P1-08）**

- 路径未确认：隐藏差额按钮，安装包不请求广告。
- 路径已确认，且 P0-15 已定稿：用原生激励视频替换 H5 `adBreak`，关掉测试模式。全游戏仍然只有这一处。

**首发内容（P1-09、P1-10、P1-12、P1-13、P1-15、P1-16、P1-32）**

- 新目的地只有夏日海滩。夏季客厅是背景，不是第二个目的地。节日皮肤只做一套，其余在 P2-09–P2-11。
- 纪念品展示间、每日心情签、拍照与分享（P1-16，P1-17 已并入）。
- P1-32：展示位、相框这类不影响旅行经济的三叶草消耗。摸摸团子已在阶段 0。

**商店材料与合规（P1-18–P1-26，外部行 P1-27–P1-30）**

- 图标、至少 5 张实机截图、横版头图、15–30 秒预告、中英简介、标签、客服邮箱、更新日志模板、隐私政策链接。
- 游戏内：健康游戏忠告、适龄提示、游玩时长提醒。隐私政策与实际 SDK 一致。

**发布（P1-31）**

- 测试区记录崩溃率、D1、D7、出发点击数和首旅完成率，再决定是否转正式页、以及之后的内容包。

### 退出标准

1. P0-17 已经通过。安装包断网冷启动能进家，网页旧档能迁过来，迁失败时旧档还在（P1-01、P1-02、P1-05）。
2. 首旅开箱之后才请求通知权限；拒绝不影响游戏。到点能收到「团子到家」（P1-03）。真机上的安全区、返回栈和四档宽度与规格一致（P1-04、P1-06）。
3. 测试包默认不请求广告。若已换原生 SDK，激励按钮只在差额状态出现（P1-07、P1-08）。
4. 展示间、海滩、夏季客厅、一套节日皮肤可玩，文字在 i18n 里（P1-09、P1-10、P1-12、P1-13）。夜市不在这个包里。
5. 心情签没有断签惩罚。拍照和分享卡是同一条合成路径（P1-15、P1-16）。三叶草有一处不影响出游的外观消耗（P1-32）。
6. 商店素材清单每一项都有文件或链接（P1-18–P1-24）。
7. 忠告、适龄、时长提醒在游戏内能打开；隐私页和实际 SDK 一致（P1-25、P1-26）。
8. P1-27 写明了能否在测试包里带激励广告之后，才做 P1-08。P1-28–P1-30 未完成不阻止无广告测试包。
9. 测试区记下崩溃率、D1、D7、出发点击数和首旅完成率之后，才转正式页（P1-31）。

## 阶段 2 — 内容包

上架之后按内容包更新。一个包最多 3 个新目的地，其中可以有 1 个季节或节日限定。系统功能用来把已经分开的线接上，每次操作保持在少数几次主动选择。

### 目标

- 用小批量内容接住「日记集完就走」的玩家。第一包把首发没做的夜市老街补上。
- 纪念品种类和目的地数量对齐，并做出套装集齐奖励。
- 系统顺序：烹饪与厨房扩展一起 → 出行装扮 → 访客图鉴 → 明信片拼图 → 存档打通的设计定稿 → 锦鲤养成。养成不能排在设计定稿前面。
- 种子买在阳台，家具买在装饰模式里（P2-25）。出行页只留食物和护符。

### 范围

目的地一次只开一包。

| 内容包 | 目的地（计入 2–3 上限） | 同包可以一起做、但不占名额 | 任务 |
| --- | --- | --- | --- |
| A | 夜市老街；竹林茶屋；枫叶溪谷（秋季限定） | 卧室 | P1-11、P2-01–P2-03 |
| B | 温泉山庄；云上邮局 | 温泉 + 雪山小木屋套装奖励 | P2-04–P2-06 |
| C | 天空图书馆；夏日花火大会（夏季限定） | — | P2-07、P2-08 |
| D（制作量更大的一包） | 海岛灯塔群、极光营地、沙漠绿洲 | — | P2-12–P2-14 |

云上邮局和天空图书馆在分析里写在同一处。若最后决定只做一个，把另一个任务标成已完成，并写明并进了哪一行。不要为了凑满两个名字而在同一包里加出第四个地点。

不占目的地名额、也不进首发清单的还有：P1 没做的那场节日加上圣诞（P2-09）、万圣节南瓜田（P2-10）、雨季水洼庭院（P2-11）。

系统与对齐：纪念品数量对齐（P2-15）、烹饪和厨房一起（P2-16、P2-17）、出行装扮（P2-18）、访客图鉴（P2-19）、明信片拼图（P2-20）、存档设计（P2-22）然后才是锦鲤养成（P2-21）、家具旋转（P2-23）、后期消耗核对（P2-24）、场景内购买（P2-25）。

好友庭院和互寄明信片不在本阶段。

### 退出标准

阶段 2 按包结束，而不是有一天「全部做完」：

1. 这一包新目的地是 2 个或 3 个。每个都有场景图、明信片、3 段递进日记，中英同时进 `assets/i18n`。包 A 算上夜市，正好 3 个。
2. 这一包约定的纪念品或套装奖励已进图鉴，旧档打开不丢已有收藏。
3. 没把下一包的目的地提前合进 `main`。
4. 限时内容结束后，已经拿到的明信片和日记还在；没有惩罚。
5. 系统任务若在本包期间合并，符合该行验收，且没有引入排行榜、体力或惩罚。P2-21 的代码在 P2-22 设计定稿之后。

P2-15 完成的标准是：有一份清单写明每个目的地对应的纪念品，缺的已经补上，或明确记在后续哪一包。

## 阶段 3 — 数据达标后

不预先开工，也不预先承诺上线。阶段 0–2 的留存数据还没被记成「可以开始」之前，任务保持待认领。

### 目标

- 多设备还能继续玩。
- 若要社交，只做异步、可关掉的轻互动，并带内容审核和防骚扰。
- 出海时补的是商店本地化和广告地区合规。游戏内英文在每条内容里已经一起交付。

### 范围

- P3-01 云存档与多设备同步。
- P3-02 先评估 TapTap 账号能不能复用。
- P3-03 参观好友庭院。P3-04 异步互寄明信片。两者都要账号、后端、审核和防骚扰，上架前不做。无后端的分享卡是 P1-16。
- P3-05 商店页本地化。P3-06 广告 SDK 的地区合规（外部，不进玩法估算）。

### 退出标准

1. 维护者在对应任务的说明里写下数据门槛已满足，以及当时看的指标，才可以认领。
2. 云存档有冲突策略：同步失败时本地档还在。
3. 社交功能默认不暴露给陌生人，有举报或拉黑一类的防骚扰路径，有内容审核方案。
4. 国际商店页的文字和实际游戏版本一致。广告地区合规未完成时，该地区包不请求广告。

## 首发前执行顺序

下面 20 步来自操作简化分析的第 5 节。人少的时候按这个顺序认领，不按 ID 大小。外部项（第 18 步）与前面的开发并行，只挡住带广告的包。

1. P0-11 信息架构合并。
2. P0-12 触控、安全区、返回栈。
3. P0-13 房间手势，池塘只留一个入口。
4. P0-15 出行页与推荐确认，含原来的 P0-10 规则提示。
5. P0-14 一键收取与开箱。
6. P1-14 摸摸团子（已提前到阶段 0）。
7. P0-01 与 P0-02：按新流程写新手引导和短首旅。
8. P0-03 与 P0-04：存档导出和 version 迁移。
9. P0-05 音效。
10. P0-06 与 P0-07：WebP 和 Three.js / Tailwind 本地化。
11. P0-16 双语和多尺寸回归。
12. P0-08 埋点（含交互漏斗）与隐私说明，加上 P0-09 兜底。
13. P0-17 可用性验收。不过关，不进 Capacitor。标准是至少 4/5 能独立完成，出发前点击中位数不超过 5。
14. P1-01–P1-07：Capacitor 打包、原生存档、回程通知、安全区和宽度的真机复验、无广告开关。
15. P1-09 展示间、P1-10 海滩、P1-12 夏季客厅、P1-13 一套节日皮肤、P1-15 心情签、P1-16 拍照与分享（P1-17 已并入）。
