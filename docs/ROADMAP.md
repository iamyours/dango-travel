# 开发路线图

《团子去旅行》继续做成轻松、治愈的放置游戏，并按这个顺序准备 [TapTap](https://www.taptap.cn/) 首发。任务认领与进度只看 [TASKS.md](TASKS.md)。协作步骤见 [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md)。背景是 [2026-11-04 设计分析](research/muse-analysis-2026-11.md) 和 [同日现状简报](research/game-brief-2026-11.md)（`main@2cad3db`）。

分析原文里的「天 / 周」是当时的工期感觉，不是本路线图的承诺。工作量用任务板上的「难度」表示。版号、软著、正式实名防沉迷是外部事项，不进开发估算。

## 硬约束

全程有效，任何阶段的 PR 都不能突破：

1. **广告只有一个。** 玩家在商店三叶草不够时，自己点「观看」才出现激励视频（rewarded ad），看完得三叶草。入口、触发和奖励含义保持现在这样。不做横幅、插屏、开屏。
2. **不做这些系统：** 排行榜、PvP、体力、失败惩罚、断签惩罚、限时错过就扣已有收藏。
3. **文案中英一起上。** 新的玩家可见文字同时写入 `assets/i18n/zh.js` 和 `assets/i18n/en.js`。逻辑用 key。不要新增硬编码中文。少做一个目的地，也不要先上中文、以后再补英文。
4. **每个内容包最多 2–3 个新目的地。** 室内房间、客厅皮肤、粒子和节日访客不算目的地。每个目的地带 3 段递进日记（中英）和可选的 1 个纪念品。
5. **`main` 随时能部署。** 站点同步与本地验证见协作约定。不要把玩到一半的 `index.html`、`assets/` 或 `koi/` 留在 `main`。

## 外部事项

下面四项由作者、出版社或 TapTap 后台推进。任务板上有对应行，方便同步状态。它们的等待时间不算进开发估算，也不要为了等它们停掉阶段 0 的网页改动。

| 事项 | 任务 | 和开发的关系 |
| --- | --- | --- |
| 版号（网络游戏出版物号） | P1-27 | 广告变现也算商业化。首发可以先走免费、无内购的测试形态。版号路径没确认前，不要上激励广告，见 P1-07。这不是法律意见。 |
| 软件著作权 | P1-28 | 建议尽早申请。不阻塞网页版改动。 |
| TapTap 开发者实名认证 | P1-29 | 入驻需要。不产生游戏代码。 |
| 正式实名与防沉迷 | P1-30 | 只有按正式版号运营时才接入。测试形态只做 P1-25 的忠告、适龄和时长提醒，不收集身份证。 |

## 现在已经有的，不要推倒重做

`main@2cad3db` 上已经有这些能力。相关任务的验收是补缺口，不是另做一套：

- 存档对象已有 `v: 3`，并有从旧 key 搬到当前 key 的一次迁移。还没有导出/导入，也还没有「以后加字段」用的迁移函数。
- 激励广告已有每日上限，按钮上会写出奖励数量。实现仍是 AdSense H5 `adBreak`，`index.html` 里 `data-adbreak-test="on"`。
- 阳台四种作物可以在厨房做成三道带目的地倾向的食物。
- 家具可以拖拽、缩放、收回。还不能旋转。
- 点团子会挥手。主游戏声音是代码里的振荡器，不是可替换的音效素材。
- 春、秋、冬客厅有独立背景。夏季分支目前用 `home_empty`。
- 页脚的隐私政策指向站点上的 `/privacy/`，页面不在本仓库。

## 阶段 0 — MVP 补完

仍在网页版。目标是第一圈循环跑得通、存档丢了有办法找回来、留存数据能看见。

### 目标

- 新玩家第一次打开就能出门，并在当天体验回家开箱。
- 玩家能自己备份存档；以后加内容时旧档不会坏。
- 打包、出发、回家这些节点有声音。
- 资源改为本地加载并压缩，给 Capacitor 包做准备。

### 范围

任务 P0-01–P0-10：

- 三步新手引导，以及一趟 5–10 分钟的新手首旅（可以用池塘当教学目的地）。
- 存档导出/导入，以及 `version` 加迁移函数。
- 基础音效包：打包、出发、回家、点击、雨声。可关闭，可混音。
- 图片转为 WebP 并压缩；锦鲤池的 Three.js r128 和 Tailwind 改为本地文件，运行时不依赖 CDN。
- 匿名埋点三个事件：首次打包、首次回程领取、次日回访。同步更新隐私说明。
- 脚本错误或加载失败时给出可恢复提示，避免整页白屏。
- 用玩家能读懂的文字说明食物、护符和稀有度如何影响目的地。

本阶段不加新目的地，不做 TapTap 包，不接原生广告 SDK。离线安装用阶段 1 的 Capacitor 解决，不另做 PWA。

### 退出标准

1. 引导在三步内完成「点 3 片三叶草 → 买最便宜的食物 → 打包」，结束时进入 5–10 分钟首旅，首旅结束能开箱（P0-01、P0-02）。普通旅程仍是大约 1–6 小时。
2. 导出的存档能在清空站点数据后导回；带 `version` 的旧档能迁移后再读（P0-03、P0-04）。
3. 上述五个声音场景可开关，广告播放时能压低音量（P0-05）。
4. 游戏图片走 WebP；锦鲤池断外网 CDN 后仍能打开（P0-06、P0-07）。
5. 三个匿名事件在测试里能对上次数，隐私说明写了事件名和用途，没有身份标识（P0-08）。
6. 故意制造脚本错误或池塘加载失败时，页面有中英提示，而不是白屏（P0-09）。
7. 稀有目的地的规则能在界面里读到，和 `chooseDest` 的实际权重一致（P0-10）。

分析里写的「首次打包转化明显高于无引导」是希望看到的方向，不是对外承诺的数字。达到上面 1–7 即可进入阶段 1 的打包与送审准备。阶段 1 的个别内容任务可以在依赖满足后并行，但 P0-01–P0-04 没人认领时，优先认领它们。

## 阶段 1 — TapTap 首发

把阶段 0 的网页做成可安装的测试包，补上 P0 场景和低难度玩法，备齐商店材料。审核和版号的日历不进本阶段的开发估算。

### 目标

- 用 Capacitor 把静态资源打进安装包，断网能开，回程有本地通知。
- 先以无广告的免费测试包验证崩溃率和留存。激励广告只在版号或类目路径确认后，换成原生 SDK。
- 补上海、夜市和收藏展示，让收集有地方放，家里也有季节变化。
- 商店页材料和游戏内合规提示齐套。测试区先跑，再转正式页。

### 范围

任务 P1-01–P1-31。

**安装包（P1-01–P1-06）**

- Capacitor 工程。不采用「一个 Activity 套网页」的裸 WebView。
- 存档迁到 Preferences 或文件，并保留原来的 localStorage 兜底。
- 出发时按回程时间预约本地通知，不需要服务器。
- 刘海安全区、安卓返回键、横竖屏锁定。
- 断网冷启动不白屏；几种分辨率各自点一遍主要界面。

**广告（P1-07、P1-08）**

- 路径未确认：隐藏激励入口，安装包不请求广告。
- 路径已确认：用原生激励视频替换 H5 `adBreak`，关掉测试模式，保留每日上限和单次奖励明示。SDK 写进隐私清单。网页版若仍和 App 共用 `index.html`，PR 要写明两边各自怎么走，避免站点同步后商店按钮失效。

**P0 场景与低难度玩法（P1-09–P1-17）**

- 新目的地只有两个：夏日海滩（普通档）、夜市老街（普通档）。
- 另外做纪念品展示间、夏季客厅背景，以及一套节日皮肤（按上线月份在春节和中秋里选一个：背景、粒子、一位节日访客）。圣诞和没选中的那个节日放在阶段 2。
- 摸摸团子、每日心情签、拍照模式、明信片分享卡。分享卡和拍照共用同一条合成路径，无后端。

**商店材料与合规提示（P1-18–P1-26，另加外部行 P1-27–P1-30）**

- 图标、至少 5 张实机截图、横版头图、15–30 秒预告、中英简介、标签、客服邮箱、更新日志模板、隐私政策链接。
- 游戏内：健康游戏忠告、适龄提示、游玩时长提醒。
- 隐私政策补上实际接入的 SDK、标识符、用途和权限。拍照保存时才申请写相册。不需要通讯录和定位。

**发布（P1-31）**

- 先上 TapTap 测试区，看崩溃率和 D1/D7，再转正式页。

### 退出标准

1. 安装包断网冷启动能进家，网页旧档能迁过来，迁失败时旧档还在（P1-01、P1-02、P1-05）。
2. 出发后能在回程时刻收到本地通知；刘海不挡按钮；返回键先关弹层和全屏池塘，再退出；方向锁定后布局完整（P1-03、P1-04、P1-06）。
3. 测试包默认不请求广告。若已换原生 SDK，全游戏仍只有这一个玩家主动触发的激励位（P1-07、P1-08）。
4. 展示间、海滩、夜市、夏季客厅、一套节日皮肤可玩，日记和界面文字中英都在 i18n 里（P1-09–P1-13）。
5. 摸摸团子、心情签、拍照、分享卡可用；心情签没有断签惩罚（P1-14–P1-17）。
6. 商店素材清单每一项都有文件或链接（P1-18–P1-24）。
7. 忠告、适龄、时长提醒在游戏内能打开；隐私页和实际 SDK 一致（P1-25、P1-26）。
8. P1-27 写明了能否在测试包里带激励广告之后，才做 P1-08。P1-28–P1-30 未完成不阻止无广告测试包上测试区。
9. 测试区记录了崩溃率和 D1/D7 之后，才转正式页（P1-31）。

## 阶段 2 — 内容包

上架之后按内容包更新。一个包最多 3 个新目的地，其中可以有 1 个季节或节日限定。系统向的功能穿插在包与包之间，用来把已经存在、但彼此分开的系统接上。

### 目标

- 用稳定的小批量内容接住「日记集完就走」的玩家。
- 纪念品种类和目的地数量对齐，并做出套装集齐奖励。
- 按这个建议顺序加深系统：烹饪 → 出行装扮 → 访客图鉴 → 明信片拼图。然后是锦鲤养成。家具旋转放在这几项之后。
- 主游戏和锦鲤池的存档是否合并，单独评估，不跟养成绑在同一次提交里。

### 范围

任务 P2-01–P2-24。目的地分成四包，一次只开一包。

| 内容包 | 目的地（计入 2–3 上限） | 同包可以一起做、但不占名额 | 任务 |
| --- | --- | --- | --- |
| A | 竹林茶屋；枫叶溪谷（秋季限定） | 卧室 | P2-01–P2-03 |
| B | 温泉山庄；云上邮局 | 温泉 + 雪山小木屋套装奖励 | P2-04–P2-06 |
| C | 天空图书馆；夏日花火大会（夏季限定） | — | P2-07、P2-08 |
| D（制作量更大的一包） | 海岛灯塔群、极光营地、沙漠绿洲 | — | P2-12–P2-14 |

云上邮局和天空图书馆在分析里写在同一处。若最后决定只做一个，把另一个任务标成已完成，并写明并进了哪一行。不要为了凑满两个名字而在同一包里加出第四个地点。

不占目的地名额、可与当前包并行的还有：P1 没做的那场节日加上圣诞（P2-09）、万圣节南瓜田（P2-10）、雨季水洼庭院（P2-11）。

系统与对齐：纪念品数量对齐（P2-15）、烹饪查漏（P2-16）、画室或小厨房扩展（P2-17，跟烹饪一起做）、出行装扮（P2-18）、访客图鉴与好感（P2-19）、明信片拼图（P2-20）、锦鲤养成（P2-21）、双存档打通评估（P2-22）、家具旋转与碰撞（P2-23）、后期三叶草消耗点（P2-24）。

好友庭院和互寄明信片不在本阶段。

### 退出标准

阶段 2 按包结束，而不是有一天「全部做完」：

1. 这一包新目的地是 2 个或 3 个。每个都有场景图、明信片、3 段递进日记，中英同时进 `assets/i18n`。
2. 这一包约定的纪念品或套装奖励已进图鉴，旧档打开不丢已有收藏。
3. 没把下一包的目的地提前合进 `main`。
4. 限时内容（花火、节日）结束后，已经拿到的明信片和日记还在；没有惩罚。
5. 系统任务若在本包期间合并，符合该行验收，且没有引入排行榜、体力或惩罚。

P2-15 完成的标准是：有一份清单写明每个目的地对应的纪念品，缺的已经补上，或明确记在后续哪一包。

## 阶段 3 — 数据达标后

不预先开工，也不预先承诺上线。阶段 0–2 的留存数据还没被记成「可以开始」之前，任务保持待认领。

### 目标

- 多设备还能继续玩。
- 若要社交，只做异步、可关掉的轻互动，并带内容审核和防骚扰。
- 出海时补的是商店本地化和广告地区合规。游戏内英文在阶段 0 之后的每条内容里已经一起交付。

### 范围

- P3-01 云存档与多设备同步。
- P3-02 先评估 TapTap 账号能不能复用。
- P3-03 参观好友庭院。P3-04 异步互寄明信片。两者都要账号、后端、审核和防骚扰，上架前不做。
- P3-05 商店页本地化。P3-06 广告 SDK 的地区合规（外部，不进玩法估算）。

### 退出标准

1. 维护者在对应任务的说明里写下数据门槛已满足，以及当时看的指标，才可以认领。
2. 云存档有冲突策略：同步失败时本地档还在。
3. 社交功能默认不暴露给陌生人，有举报或拉黑一类的防骚扰路径，有内容审核方案。
4. 国际商店页的文字和实际游戏版本一致。广告地区合规未完成时，该地区包不请求广告。

## 建议的认领顺序

人少的时候按这个顺序认领，而不是按 ID 数字的大小：

1. P0-02、P0-01、P0-04、P0-03（第一圈和存档）。
2. P0-05、P0-08、P0-09、P0-10。
3. P0-06、P0-07，然后才是 P1-01。
4. P1 的场景和低难度玩法可以跟 2、3 并行，但不要抢在 1 前面把人都吸走。
5. 阶段 2 从内容包 A 开始，系统任务按「烹饪 → 装扮 → 访客 → 拼图 → 锦鲤」认领。
6. 阶段 3 等数据门槛写进任务说明。
