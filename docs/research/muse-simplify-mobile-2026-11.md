# Muse：团子去旅行 操作简化与手机端方案

来源：Muse 线程 https://muse.ai/thread/1a114539-57f4-4a92-b8a4-41f3c5136ee3（2026-11-04，附 390×844 实测截图 mobile/sheet.jpg）

以下按附图实测的 390×844 界面拆。核心判断先说：不要在现有 7 标签上再加一层底部导航，要先做信息架构合并，再做 Capacitor 套壳，否则只是把繁琐原样搬进 App。

基线先算清：以草地 8/8 成熟计，现在完成一次出发是 Garden(1) → 点三叶草(8) → Shop(1) → Buy 食物(1) → Buy 护符(1) → Bag(1) → 选食物(1) → 选护符(1) → Pack(1)，共 16 次点击、3 次切页，还不含滚动找商品和误点；回家后收明信片、看日记、查相册又是另外 3-5 次跳转。

1. 冗余与繁琐操作：逐项合并方案
现状	问题	改法（具体去向）
顶栏 7 个小按钮：中/EN、三叶草、3D、🐟、🔈、×1 等，约 24pt	全是小靶子，且多数不是高频任务	顶栏只留 4 个元素：标题 / 🍀余额 / 中-EN / ⋯更多，每个点击区 ≥48pt。声音开关、速度 ×1、存档导出、设置、隐私、帮助全部收进 ⋯ 的列表页（每行 48pt）。时间/季节/天气不是操作，降为首页场景下方的状态文字
7 个一级标签 Home/Pond/Garden/Shop/Bag/Diary/Album，约 48×36pt	宽度不够、高度不够、英文词长短不一，且按「页面」而非「玩家要做的事」分类	合并为 4 个底部 Tab：家 Home / 出行 Trip / 池塘 Pond / 收藏 Keepsakes。理由见下
Garden 独立成页	采三叶草是每次出发的前置劳动，不是一个目的地	取消 Garden 标签。庭院并入「家」的场景轮换（一滑就到），三叶草在庭院场景内收，余额不足时在出行页也能看到成熟数量和一键收取入口
Shop 与 Bag 分两页	「买」和「选」被人为拆开：商店 Buy 完还要记住自己买了什么，再去 Bag 里找出来点一遍	合为一个「出行」页：上半选行囊、下半是同页的补给区，选到未拥有的物品时由出发按钮一次性结算（详见第 2、3 节）。种子、家具仍可在同页的「补给」分段里买，不再单独占标签
Diary 独立成页	低频、且和明信片同属「旅行回忆」	并入「收藏」页内的分段：明信片 Postcards / 日记 Diary / 纪念品 Souvenirs / 合影 Photos。分段只在收藏页内部出现，不再是一级导航
房间药丸 6 个（27pt）+ 场景左右 ‹ › 箭头，两套并存	同一件事（换房间）有三个入口：药丸、箭头、还有 Pond 标签	二选一留手势：手机端删除药丸行、隐藏 ‹ ›，改左右滑换房间 + 场景下方圆点指示 + 一枚可点的当前房间名胶囊（点开是房间列表 Sheet，每个房间一行 52pt，含「有访客/菜熟了」角标）。‹ › 只在平板/网页宽屏保留
Pond 出现 4 次：标签、房间药丸、顶栏 3D、顶栏 🐟	同一功能四入口，玩家分不清 2D 池塘房间和 3D 锦鲤池是不是一回事	统一为一个入口：底部「池塘」Tab 进入池塘场景，场景内一枚 56pt 主按钮 进入 3D 锦鲤池 Enter 3D Pond 进入全屏沉浸模式。顶栏 3D/🐟 删除，房间列表里不再有 Pond
首页的 Decorate 按钮（25pt）、纪念品卡、页脚链接（21pt）纵向堆叠	首页首屏被低频信息占满，团子状态反而被挤	Decorate 改为室内场景右下角的悬浮编辑按钮（48pt 圆形，只在室内房间出现）；纪念品卡删掉，改为「收藏」Tab 红点 + 首页一行可点的目标进度 下一目标：明信片 3/13 ›；页脚链接全部移入 ⋯ 设置页
Diary 的 ‹Prev/Next›（24pt）+ 页数	翻页靶子太小	改为在日记卡片上左右滑翻页，底部保留一对 48pt 翻页按钮作可发现性兜底，另加 目录 Index 按钮打开日期列表
Album 里满屏「?」格子	只知道没集齐，不知道去哪集、还差什么	「?」格子可点：点开显示剪影/目的地名/稀有度/「还没去过 · 日记 0/3」提示（与 P0-10 目的地规则说明合并），空格子从死 UI 变成目标指引
语言默认英文	附图全为英文默认，TapTap 中文用户首启不应如此	首启跟随系统语言（Capacitor 取 locale），手动切换后持久化保存；中/EN 切换保留在顶栏是因为双语是硬约束，不能埋进设置三层深
改后点击数

常规出发：一键收取(1) → 点出行页主按钮打开确认层(1) → 就这样出发(1) = 3 次、0 次切页（收取按钮就在首页）。自己调组合：5 次封顶。
回家开箱再出发：点通知/首页包裹(1) → 收下全部(1) → 再来一次(1) → 出发(1) = 4 次。
即从 16+ 次降到 3-5 次，降幅约 75-80%，且省掉的是纯劳动点击，保留的是确认类点击。
2. 手机布局与交互方案
统一尺寸规范（写成设计令牌，全站执行）

--tap-min: 48px：所有可点元素点击区 ≥48×48（iOS 44pt / Android 48dp 取大者），视觉可以小，但用 padding 撑满点击区；相邻靶子间距 ≥8px。
一级按钮高 56pt、次级 48pt、正文 ≥14pt、辅助文字 ≥12pt，禁止再出现 21-27pt 的功能行。
底部导航：高 64pt + env(safe-area-inset-bottom)；顶部：安全区 + 56pt 顶栏。场景、按钮一律不压刘海和底部横条；所有吸底元素（主 CTA、喂鱼条）用 bottom: calc(64px + safe-area) 计算。
双语布局：导航用短词（家/出行/池塘/收藏 对 Home/Trip/Pond/Keepsakes），英文下主按钮允许 56pt 内单行不截断，验收宽度 360/390/430 三档 + 平板居中列（最大宽 600px，导航同宽居中，不做第二套横屏 UI）。

3. 一键与自动化：减什么、留什么
一键打包（推荐组合）怎么做才不剥夺选择

首页主 CTA 点击后不是直接把团子送走，而是打开确认 Sheet（出发是数小时不可逆操作，必须有确认）：



这次这样去？
[艾草团子 1-2h] + [森林护符]     换一组 ↻ | 我自己选 ›
为什么推荐：还没去过的地方优先 · 时长适中 · 最省三叶草
合计 🍀17（出发时购买） · 预计 1-2 小时
[ 就这样出发 Depart ]  56pt
推荐逻辑只依据玩家在本页选的目标胶囊（随便走/找新地方/去远方/快点回）+ 未集满日记优先 + 余额，三条理由明写在 Sheet 上，玩家一眼知道机器替他决定了什么。换一组 在同目标内轮换组合，我自己选 落到第 2 节的完整出行页。
一键收取：庭院场景浮出 [收三叶草 ×8]，点击后三叶草飞向顶栏余额（保留爽感动画）；幸运四叶草不自动收，仍需点中那一株，给个小惊喜音效 — 自动化不该吃掉彩蛋。
一键开箱：回家后包裹是一个整体，点开自动依次翻明信片 → 纪念品入展示间 → 日记归档，最后只点一次 收下全部。三样东西在打开动画开始时就已写入存档，动画中途关 App 不丢、不重复领。
再来一次：开箱结果页和出行页各有一个 再来一次（同组合），库存够就直接进确认 Sheet；不够时按钮显示差额，不静默换组合。
顺手的一键：阳台 一键收获 / 一键种满空地（按推荐）、锦鲤 按住连喂，都属于同类劳动，同一原则处理。
必须保留手动的四件事及原因

出发时机和时长档 — 旅行占真实时间 1-6 小时，跟玩家当天安排有关，自动出发等于替玩家做生活决策。
护符/目标取舍 — 这是全游戏唯一的策略层（去向概率 vs 成本），自动化掉它，游戏就只剩收菜。
任何扣三叶草的首次购买和大额购买 — 推荐可以预选，扣费必须经确认 Sheet 明示合计与余额。
装饰摆放 — 这是创作表达不是劳动，拖拽本身就是玩法（P2-23 的旋转/碰撞仍留手动场景内做）。
激励广告的唯一位置

放在出行确认 Sheet / 出行页的差额状态里，这是全游戏唯一入口：当 余额 < 本次合计 时，确认 Sheet 里主按钮下方出现一条次级描边按钮 🎬 看视频补三叶草 +30（还差 12），点后才播，播完即时到账、Sheet 不关闭，玩家接着点出发。规则：教程首旅不出现（首旅必须免费/可负担）；余额够时不露出（顶栏、庭院、开箱、池塘都不放）；不自动弹、不与出发按钮合并成「看广告才能走」；每日上限和奖励数在按钮上明示。这一处符合「玩家自愿」且动机最真实 — 他正想出发，就差一点。

4. 低操作下的可玩性：靠「有事发生」，不靠「有活要干」
点击变少后，每日体验应重构成三个短时段：早上 30 秒（一键收取 → 选目标 → 出发）、白天可选 1 分钟（看访客/喂鱼/收菜）、晚上 1 分钟（开箱 → 读日记 → 再来一次）。新鲜感由内容变量供给，每次回访至少有一件新事：

优先级	内容/玩法	每次操作量	成本（相对）与依赖
P0	回程仪式感：开箱三段揭晓 + 3 段递进日记质量 + 到家本地通知（P1-03，授权请求放在首旅回家后、不要首启弹）	1 点开箱	低，已有系统，主要是文案双语量

P0	访客事件：访客出现在场景里（气泡角标），点开一句对话+一份礼物，不点也不惩罚、不过期惩罚	1-2 点	低，复用已有 6 访客，加台词即可
